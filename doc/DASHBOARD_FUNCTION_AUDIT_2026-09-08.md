## 판정 기준

- **조회 확인**: 실제 HTTP 요청의 성공 또는 브라우저 표시를 확인했다. 데이터의 투자 적합성·증권사 원장과의 완전 일치를 뜻하지 않는다.
- **동작 확인**: 별도 DB의 격리 서버에서 변경 요청과 결과를 직접 확인했다.
- **자동 검증**: 관련 unittest를 실행했다. 모든 화면 버튼을 실계좌에서 눌렀다는 뜻이 아니다.
- **제한/미확인**: 외부 실행, 파괴적 조작, 숨김 화면 등 이번 실행으로 입증하지 못한 부분이다.
- 운영 서버에서는 조회만 수행했다. 실주문·승인·전량매도·DB 초기화·Slack 발송은 실행하지 않았다. 주문 관련 변경은 모의/목업 테스트로 확인했다.
- 격리 서버는 별도 작업 디렉터리·DB·설정 파일을 사용하고 `DRY_RUN=true`, `TRADING_ENV=demo`, `ENABLE_LIVE_TRADING=false`, `REQUIRE_APPROVAL=true`, `ONLINE_ACCESS_BLOCKED=true`로 실행했다.

## 남은 확인 범위와 목표

1. 증권사 주문 접수→부분체결→취소→재주문 종단 검증: 별도 모의계좌와 장중 조건에서 주문번호·체결수량·잔고·승인 상태를 대조한다. 이번에는 목업 자동 검증까지 수행했다.
2. AI 분석·최적화·전체 스케줄: 실제 데이터/모델 응답을 사용하는 별도 실행 회차의 입력·비용·결과·주문 차단 여부를 확인한다. 이번에는 운영 자동화를 강제 실행하지 않았다.
3. 파괴적 데이터 기능: DB 초기화·운영 거래 삭제·잔고 일괄 보정은 백업한 별도 데이터셋에서 대상 범위와 복원 가능성을 검증해야 한다. 이번 운영 DB에는 실행하지 않았다.
4. 숨김 화면/기능: 신규 AI전략 등록 버튼과 폼은 `style.css`의 `display: none !important`로 숨겨져 있다. API 등록은 정상 확인했지만 화면 등록은 접근 불가다. 최적화 일괄 승인등록 역시 기본 숨김이다.  급락반등/하이킨아시 전략은 공통 AI전략·진단·스케줄과 별도로 과거 전용 화면 코드가 남아 있다. 메뉴 복구를 임의로 하지 않았으며 전용 화면 버튼 정상 여부는 미확인이다.
5. 데이터 정확도: HTTP 200은 원장 금액의 완전 일치를 보장하지 않는다. 거래비용·입출금·전략 귀속·당일/누적 손익은 증권사 원장 대조가 추가로 필요하다.
