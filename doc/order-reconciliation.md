# 주문·체결·잔고 현행화

주문 접수 성공은 `submitted`이며 체결 완료가 아니다. 실제 체결수량과 가격은
증권사 주문체결내역에서 확인한다. 잔고는 계좌 전체의 보유량을 보여 주므로
외부 주문, 다른 전략 주문, 입출고가 섞일 수 있다.

## 확인 및 복구

- 주문 직후 기본 3초 대기 후 체결 확인을 시작하며 5초 간격으로 총 3회 시도한다.
  실제 간격에는 조회 시간이 추가된다. 전략 실행 전후에도 확인한다.
- 주문 상태 조회는 미완료 주문의 주문일별로 조회한다. `days=1`은 당일이며,
  이전 날짜의 미완료 주문도 누락하지 않는다.
- 통합 원장에만 존재하는 주문도 계좌·시장 조건으로 조회한다.
- 전체 동기화는 요청 기간의 체결내역을 가져오고 최신 잔고와 포지션을 비교한다.
- 잔고 차이만으로 체결, 체결가격, 취소 또는 승인 실행을 확정하지 않는다.
  증거가 없으면 기존 주문 상태와 체결량을 보존하고 `review_required`로 표시한다.
- 신규 증권사 체결내역은 통합 주문·체결·포지션에 반영한다. 같은 누적 체결을
  재조회해도 체결이나 포지션을 중복 증가시키지 않는다.
- 잔고 수량의 운영자 보정은 현재 계좌·시장에만 적용되며 현금흐름을 만들지 않는다.

## 장애 처리

- 잔고 및 일별 체결내역의 모든 연속 페이지를 받아야 조회에 성공한다.
  후속 페이지 오류, 반복 커서, 누락 커서, 페이지 한도 도달은 조회 실패다.
- 인증 갱신 후 조회 재시도는 원래 요청 본문을 보존한다. 주문 전송은 자동으로
  재시도하지 않는다.
- 재시작 시 전일 미완료 주문은 `broker_unknown`으로 전환해 최종 증권사 확인을
  기다린다. 기존 시작 복구가 자체 만료 처리한 기록도 감사 이벤트/메시지로
  식별되는 경우 재확인 대상으로 돌린다. 증권사 확인으로 취소된 주문은 유지한다.
- 체결가격이 누락된 체결은 현재가·주문가로 대체하지 않고 검토 대상으로 남긴다.
- 화면 잔고는 기본 30초 캐시이며 조회 실패 시 과거 캐시를 보여 줄 수 있다.
  전체 동기화와 매도 직전 검증에는 이 화면 캐시를 사용하지 않는다.

## 기존 데이터 호환성

새 거래는 계좌·환경·시장에 따른 계좌 키를 저장한다. 계좌를 구분하지 못하는
과거 환경 전용 키/빈 키 기록은 현재 계좌에 임의 배정하지 않는다. 현재 계좌의
통합 주문과 승인 ID 또는 명시적인 거래 ID로 연결된 기록만 자동 대사한다.
주문번호가 다른 날짜에 재사용돼도 다른 날의 주문을 덮어쓰지 않는다.

과거 잔고 추정으로 이미 생성된 체결을 이 변경이 일괄 삭제하지는 않는다.
실제 증권사 체결내역과 감사 이력을 대조한 후 별도로 정정해야 한다.

## 검증

`tools/verify-local.ps1`과 `tools/check-encoding.ps1`을 실행한다.
핵심 회귀 테스트는 `test_broker_sync_integrity.py`,
`test_reconciliation_dashboard.py`, `test_order_history_service.py`,
`test_order_sync_terminal_isolation.py`, `test_unified_order_ledger.py`에 있다.
네트워크 응답은 모킹하며 실제 주문이나 운영 계좌 데이터 정정은 실행하지 않는다.
